# 后台管理系统（主人专属）实现计划

## 背景

当前服务端的能力边界全部固化在 `config.yaml` + 环境变量里：改 API Key 要改文件重启，主人身份写死为 `Bot.ControlQQ` 单个值，模型能调用的 OneBot 接口没有任何准入控制，文档类需求完全依赖模型自由发挥。用户希望有一个仅管理员可进的后台，把这些运行期开关收敛到网页里，并补齐三块能力：多媒介能力开关、PDF/Word/Excel 生成发送、回复后的自主分段发送。

已确认的口径（来自提问回答）：

* 后台用**独立管理员账号**，与普通用户账号体系隔离。

* 「Napcat 端口」= **功能/接口级开关**（图片、表情、语音、视频、群文件等），不是 TCP 端口。

* 文档能力 = **模板化生成 + 编辑发送**；普通 QQ 用户也可提出需求，每人每天最多产出 2 个文件；信息不足时允许机器人多轮主动追问，凑齐后再生成发送。

* 自主分段发送 = **机器人回复后按配置延时自动补发第 2..N 段**，仅对主人或白名单 QQ 生效。

## 总体设计

新增 4 个后端模块 + 1 个前端页面：

```
server/internal/
  admin/      管理员账号、JWT(scope=admin)、初始化
  settings/   运行期配置（SQLite 持久化 + 内存快照 + 变更回调）
  docs/       xlsx/docx/pdf 生成、上传到 NapCat
  bot/        (改造) 能力准入、owner 名单、followups、doc 契约
client/src/pages/admin/   后台页面（含独立登录）
```

### 1. 管理员账号与鉴权

* 迁移新增 `admins(id TEXT PK, username TEXT UNIQUE, password_hash TEXT, created_at, updated_at, last_login_at)`。

* 启动时若表为空：读 `ADMIN_PASSWORD` 环境变量创建 `admin` 账号；未配置则跳过创建并在日志 `WARN`（不打印密码）。

* 密码沿用 `internal/auth` 现有的 bcrypt/hash 实现，不新造轮子。

* 管理员 JWT 独立签发：claims 带 `scope=admin`、`sub=admin:<id>`，复用 `auth.JWTManager` 但使用不同的 audience/claim 校验。

* 中间件 `requireAdmin` 只挂在 `/api/v1/admin/*`，不改现有用户路由。

### 2. 运行期配置（settings）

* 迁移新增 `settings(key TEXT PK, value TEXT, updated_at)`，存 JSON 值。

* `settings.Store` 提供 `Snapshot()`（`atomic.Value`）与 `Update(patch)`：写库 → 更新快照 → 触发注册的回调。

* 启动顺序：`config.Default()` → 读 yaml → 覆盖 `ADMIN_*` 等环境变量 → 再用 DB settings 覆盖可热改项。

* 可热改项：`deepseek.api_key/base_url/model/enable_thinking`、`capabilities`、`auto_segment`、`owner_qqs`、`doc_quota_per_day`。

* **LLM 客户端改造**：`summarize.Client` 目前把 `ClientConfig` 存在不可变字段里。改为持有 `atomic.Pointer[ClientConfig]`，新增 `Update(cfg)`；`doChat`/`ChatStream` 每次调用前 `load()`。这样后台改 key 立即生效、无需重启。

* 安全：`GET /admin/settings` 对 `api_key` 只返回掩码（`sk-...abcd`）；`PUT` 空字符串表示不修改。

### 3. 主人名单（owner 权限）

* 迁移新增 `owner_qqs(qq TEXT PK, note TEXT, created_at)`；`Bot.ControlQQ` 作为内置主人始终保留（不可删除）。

* `bot.Service` 增加 `isOwner(qq)`，替换现有散落的 `ev.UserID == s.cfg.ControlQQ` 判断（[bot.go](file:///C:/Users/Surface/Documents/Trae-CN/default/server/internal/bot/bot.go#L98-L142)、[userLabel](file:///C:/Users/Surface/Documents/Trae-CN/default/server/internal/bot/bot.go#L467-L477)）。

* 名单变更通过 settings 回调刷新内存集合，无需重启。

### 4. 多媒介能力开关

* 设置结构 `capabilities: {image, sticker, voice, video, file, recall, at_all}`。

* 在 `bot.runOnebotAPI`（[bot.go L381-401](file:///C:/Users/Surface/Documents/Trae-CN/default/server/internal/bot/bot.go#L381-L401)）调用前解析 `action` 与 `params`，映射到能力类别；关闭时直接返回 `"该能力已被管理员关闭"` 作为工具结果，模型会自然转述。

* 同时过滤纯文本回复里的 CQ 码：关闭 `image/sticker/voice/video` 时，从 `final` 中剔除对应 `[CQ:image,...]`、`[CQ:face,...]` 等片段（新增 `bot/sanitize.go`），避免绕过开关。

* 分类映射集中在 `internal/bot/capability.go` 一张表里，便于以后扩展。

### 5. 文档生成与发送

* 新增 `internal/docs`：

  * `xlsx`：复用已有 `github.com/xuri/excelize/v2`（已在 go.mod），支持从模板文件加载后改单元格，或从零建表。

  * `docx`：用 `archive/zip` + OOXML 模板生成（无新增依赖）；支持标题/段落/表格。

  * `pdf`：新增依赖 `github.com/go-pdf/fpdf`；中文需嵌入 TTF，部署时从 `/usr/share/fonts/.../NotoSansCJK-Regular.ttc` 取字体，找不到字体则报错并回退为生成 docx（明确记录）。

* 输出目录 `data/docs/<uuid>.<ext>`，同时登记 `doc_files` 表（`id, user_qq, chat_key, filename, type, size, created_at`）用于配额与后台审计。

* 发送：`CallAction("upload_group_file", {group_id, file:"file:///abs/path", name})`；私聊用 `upload_private_file`。NapCat 与本服务同机，走本地绝对路径。

* 机器人契约扩展（`aiReply` 增加 `doc` 字段）：

```json
"doc": {
  "action": "ask" | "create",
  "type": "xlsx" | "docx" | "pdf",
  "title": "...",
  "sections": [{"heading":"...","body":"..."}],
  "rows": [["表头1","表头2"],["值1","值2"]],
  "questions": ["还差什么信息"]
}
```

* 多轮收集：新增 `doc_drafts(chat_key PK, type, slot_json, updated_at)`。`action=ask` 时存槽位并回复 `questions`；下一轮把已有槽位注入 prompt；`action=create` 且必填齐全时生成并发送，清空草稿。

* 配额：生成前查 `doc_files` 当日条数，`>= doc_quota_per_day`（默认 2）则回复额度用尽。

* 输入素材：用户发来的 pdf/word/excel 走现有 `contentfetch/docparse.ParseBytes` 提取文本，作为 `source_text` 注入 prompt（截断到配置上限）。

### 6. 自主分段发送

* 设置结构 `auto_segment: {enabled, targets:["owner"|"qq"], min_delay_ms, max_delay_ms, max_segments, start_index}`。

* `aiReply` 增加 `followups []string`；`bot.chat` 在主回复 `send` 完成后，若 `enabled` 且发送者在 targets 内，则按随机间隔（`min~max`）逐条发送 `followups`，最多 `max_segments` 条，遵循 `start_index` 决定从第几条开始补发。

* 发送使用现有 `s.send`，复用其超长分片与 @ 逻辑；发送前检查 `ctx` 是否已取消，避免服务重启后继续吐消息。

* 提示词里明确：`followups` 只在需要补充说明时使用，且不得与主回复重复。

### 7. 后台 API（`/api/v1/admin`）

| 方法              | 路径                       | 说明                             |
| --------------- | ------------------------ | ------------------------------ |
| POST            | `/login`                 | 管理员登录，返回 admin JWT             |
| GET             | `/me`                    | 当前管理员信息                        |
| GET/PUT         | `/settings`              | 读（key 掩码）/写运行期配置               |
| POST            | `/settings/test-llm`     | 用当前 key 发一条最小请求验证连通性           |
| GET/POST/DELETE | `/owners`                | 主人名单增删查                        |
| GET             | `/status`                | 服务运行状态：NapCat 连接、模型配置、今日文档数、版本 |
| GET             | `/doc-files?limit=50`    | 最近生成的文档审计列表                    |
| POST            | `/doc-files/{id}/resend` | 重新发送指定文件                       |

所有写操作记录 `admin_audit(id, admin_id, action, detail, created_at)`，后台页面可看最近操作。

## 实施顺序

1. **迁移 + 设置层**：建表、settings 快照、LLM 客户端热更新。此步完成后改 key 无需重启。
2. **管理员鉴权**：账号初始化、登录、`requireAdmin`、后台路由骨架 + `/status`。
3. **后台页面**：登录 + 模型配置 + 状态卡片，先打通端到端最小闭环。
4. **主人名单 + 能力开关**：owner 表、`isOwner` 重构、`runOnebotAPI` 准入、CQ 码清洗、后台对应面板。
5. **自主分段发送**：契约扩展 `followups`、白名单与延时发送、后台面板。
6. **文档能力**：`internal/docs` 三种格式、`doc` 契约与多轮草稿、配额、上传发送、后台审计面板。
7. **构建与部署**：交叉编译 → 上传 → 备份 → 重启 → 健康检查；同时更新发布目录产物。

## 验证方式

* **单测**：`settings` 覆盖优先级、`isOwner`、能力映射、CQ 码清洗、docx/xlsx 生成后可被现有 `docparse` 反解出文本。

* **接口**：用 curl 走一遍管理员登录 → 改 key → `test-llm` 返回 200 → 改能力开关 → `/status` 反映变化；错误的普通用户 token 访问 `/admin/*` 必须 403。

* **QQ 实测**：群内 @ 机器人发一张图（开关开/关各一次）；主人私聊要求「做一个本周作业清单的 Excel」并观察多轮追问与最终文件；触发一次自主分段，确认第 2..N 条按间隔到达。

* **回归**：日程摘要、`/healthz`、NapCat 反向 WS 重连、Windows/Android 客户端登录均不得受影响。

## 风险与取舍

* **PDF 中文字体**：fpdf 需嵌入 TTF；若服务器字体缺失，PDF 会退化。计划里保留「找不到字体则改发 docx」的降级路径，并在后台状态页展示字体是否就绪。

* **`upload_group_file`** **的本地路径**：NapCat 对 `file:///` 绝对路径的支持需在部署后实测；若只接受 URL，则改由服务端暴露 `GET /files/{id}` 一次性下载链接再传 URL。

* **热更新面**：本次只让 LLM key/模型、能力开关、owner 名单、分段参数可热改；监听端口、数据库路径等仍需重启，避免过度设计。

* **范围**：不做在线可视化排版编辑器（按用户选择走模板化生成），不做真实 TCP 端口启停。
